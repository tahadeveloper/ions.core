# Phase 4.6 — Illuminate 10 → 11 (+ Symfony 7, Monolog 3, Pest 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`). Several tasks are **exploratory dependency upgrades** (resolve → observe → fix loops), not pre-written code — the test suite (**192 tests**) + Rector are the safety net. Marked accordingly.

**Goal:** Complete the framework's move onto modern, fully-supported foundations: **Illuminate 11**, which forces **Symfony 7** components and **Monolog 3**, and unblocks **Pest 3 / PHPUnit 11**. This is the last big upgrade; afterward the only remaining work is Phase 6 (release polish).

**Architecture:** No architecture change — a coordinated major dependency bump on top of the Phase 2–5 container/provider/middleware/auth design. The Phase 5 `UserProvider` abstraction is the linchpin: it makes Cartalyst Sentinel **optional**, so Illuminate 11 can proceed even if Sentinel has no L11 release (default the provider to the native `EloquentUserProvider`).

**Tech Stack target (post-phase):** PHP 8.2+, **Illuminate 11.x**, **Symfony 7.x** (config, mailer, routing, security-csrf, translation, yaml + http-foundation/routing via Illuminate), **Monolog 3.x**, **Pest 3 + PHPUnit 11**, `lcobucci/jwt` 5, `league/flysystem` 3, `spatie/ignition`/`filp/whoops` (verify L11/PHP-8.2 compat). Cartalyst Sentinel: L11 release if it exists, else optional.

**Branch:** fresh branch off `main` (e.g. `phase4.6-illuminate11`). `main` holds Phases 0–5 (192 tests green) on Illuminate 10 / Symfony 6.4 / Monolog 2 / Pest 2.

## ⚠️ Decision D-S(11) — Cartalyst Sentinel's fate at Illuminate 11 (resolve in Task 4.6.0 FIRST)
`cartalyst/sentinel:^7.0` (current) targets Laravel 10. **Whether a Sentinel release supports Laravel/Illuminate 11 is unknown and must be verified first.** Phase 5 already shipped the abstraction (`UserProvider`) + a native `EloquentUserProvider`, so this is no longer a hard blocker — but it determines the path:
- **Path 1 — Sentinel has an L11 release:** bump `cartalyst/sentinel` to it; keep it the default provider; straightforward.
- **Path 2 — Sentinel has NO L11 release (likely):** make Sentinel **optional**:
  - Move `cartalyst/sentinel` from `require` to `suggest` (or a `require-dev` for the Sentinel adapter tests only).
  - **Guard the Sentinel-coupled code so the package works without Sentinel installed.** The blocker: `src/Auth/Guard/Guard.php` calls `Guard::constructStatic()` at file-load (bootstraps Sentinel) — autoloading it without Sentinel present fatals. Fix: remove the file-load bootstrap (lazy-init Sentinel inside the methods, guarded by `class_exists(Sentinel::class)`), and make `SentinelUserProvider` throw a clear "Sentinel not installed" error only if used without the package. `GuardUser/GuardRole/GuardControl/Auth\Sentinel\*` similarly become optional.
  - **Switch the default `auth.provider` to `eloquent`** (the native provider) so the framework's own auth needs no Sentinel.
  - The Sentinel adapter tests (`SentinelUserProviderTest`, `GuardTest`) require Sentinel — gate them with `->skip()` when Sentinel isn't installed, OR keep `cartalyst/sentinel` in `require-dev` so CI still runs them.
  
  **Recommended for Path 2:** keep `cartalyst/sentinel` in `require-dev` (so the adapter + Guard tests keep running in CI) but OUT of `require` (so host apps aren't forced onto it / it doesn't pin Illuminate), move it to `suggest` for consumers, default `auth.provider=eloquent`, and lazy-guard the Guard bootstrap. This keeps full test coverage while unblocking Illuminate 11.

**Surface the D-S(11) finding to the user after Task 4.6.0** (it changes scope: Path 2 adds the Sentinel-optional refactor).

> **RESOLVED (4.6.0 investigation, 2026-06-09): PATH 1.** `cartalyst/sentinel:^8.0` (v8.0.0) supports Illuminate 11 — a full `composer update --dry-run` of the whole `illuminate ^11 + symfony ^7 + monolog ^3 + sentinel ^8` set resolves cleanly (sentinel v7.0.2→v8.0.0, illuminate→v11.51, symfony→7.4, monolog→3.10, termwind→2.4) with **no conflicts**. **No Sentinel-optional refactor is needed** — just bump `cartalyst/sentinel` to `^8.0` in `require` with the rest; keep it the default provider. The Path-2 prerequisite refactor (Task 4.6.0 "If Path 2" section) is SKIPPED.

## Known BC breaks (verified against the code; the upgrade tasks will hit these)
1. **Symfony 7 renames the routing attribute loaders.** `src/Foundation/Kernel.php` uses `Symfony\Component\Routing\Loader\AnnotationDirectoryLoader`; `src/Bundles/AttributeRouteControllerLoader.php` extends `Symfony\Component\Routing\Loader\AnnotationClassLoader`. In Symfony 7 these are **`AttributeDirectoryLoader`** / **`AttributeClassLoader`** (the `Annotation*` names were removed). Both files must switch.
2. **Monolog 3 removed `FirePHPHandler`.** `src/Bundles/Logs.php` uses `Monolog\Handler\FirePHPHandler` (and `Monolog\Logger::DEBUG`). `FirePHPHandler` does not exist in Monolog 3 → fatal. Remove it (it's a legacy browser-debug handler). Verify `Logger::DEBUG` (Monolog 3 keeps the int constant but prefers the `Monolog\Level` enum; `StreamHandler` accepts `int|string|Level`) — keep working or switch to `Level::Debug`. `Logs::create()` returns a `Monolog\Logger` — its `error()/warning()` message+context API is unchanged (no custom handlers/processors consume the new `LogRecord` object, so the M2→M3 record-shape change doesn't bite here).
3. **Pest 3 / PHPUnit 11** were blocked by `nunomaduro/termwind ^1` (Illuminate 10 console). Illuminate 11 ships `termwind ^2`, unblocking `pestphp/pest:^3` (which pulls PHPUnit 11). Migrate any Pest 2→3 deltas; update `phpunit.xml` schema if required.
4. **Spatie Ignition / Whoops:** verify `spatie/ignition:^1.15` and `filp/whoops:^2.15` resolve on the Illuminate-11/PHP-8.2 set; bump if needed (Ignition has a 1.x line for PHP 8.2). These are only used... actually Ignition/Whoops were REMOVED from `Kernel` in Phase 3.3.2 (the `ExceptionHandler` replaced them) — confirm they're no longer imported in `src/`; if unused, they can be DROPPED from `require` entirely (a nice cleanup). Grep `Ignition`/`Whoops` in `src/`.

Mitigate: stage the *independent* prep (4.6.0 Sentinel-optional, 4.6.1 loader rename, 4.6.2 FirePHP removal) FIRST on Illuminate 10 so the actual bump (4.6.3) has the smallest possible delta.
